# Repository README (baseline understanding)

## Purpose

Personal academic website of Mitchell Tillman, PhD (biomechanics, Shirley Ryan AbilityLab), served at `www.mitchelltillman.com` (see `CNAME`) from the GitHub repo `mtillman14/mtillman14.github.io`. It is a heavily customized fork of the **Academic Pages** Jekyll template (itself derived from Minimal Mistakes). The top-level `README.md` is the upstream template's README and does **not** describe the customizations — this section does.

On top of the template, the repo adds a **content pipeline** so that one set of source files feeds both the website and an auto-generated PDF CV:

- Publications are pulled from ORCID → BibTeX → `_publications/*.md`.
- Talks come from `site_updater/talks.csv` → `_talks/*.md`.
- A Leaflet talk map is geocoded from the talks.
- The CV PDF (`files/cv.pdf`) is rendered from the same markdown/YAML via a Jinja2 → LaTeX (moderncv) template.

## Tech stack

- **Jekyll 3.10** (Ruby, `Gemfile`), kramdown GFM, plugins: feed, gist, paginate, sitemap, redirect-from, jemoji. Theme Sass in `_sass/`, JS bundled to `assets/js/main.min.js` via `npm run build:js` (`package.json`).
- **Python 3** scripts in `site_updater/` (deps in `site_updater/requirements.txt`: requests, pybtex, pandas, getorg, geopy, jinja2, pyyaml). A local `.venv/` exists on the user's machine. **Python is not available in the Claude sandbox** (see NOTE 1).
- **LaTeX** (moderncv) for the CV; compiled by `latexmk` locally if installed, and always in CI.
- **GitHub Actions** (`.github/workflows/pages.yml`) builds and deploys the site — not the legacy github-pages gem.
- Third-party integrations: giscus comments (`_includes/comments-providers/custom.html`), Google Analytics 4 (`_includes/analytics-providers/custom.html`).

## The content pipeline (`site_updater/`)

All scripts are run **from inside `site_updater/`** (they use relative paths like `../_talks`). `update_research_output.zsh` runs them in this order with `set -e`:

1. **`OrcidToBib.py`** — Queries the public ORCID v3 API for ORCID `0000-0002-3115-1587`, collects each work's attached BibTeX citation, and overwrites `output.bib` only if every request succeeded and at least one citation came back. Works without a BibTeX citation on ORCID are silently skipped.
2. **`pubsFromBib.py`** — Parses `output.bib` with pybtex and writes `_publications/YYYY-MM-DD-<slug>.md`. Venues containing "proceeding" are filed as `category: conferences`, else `manuscripts`. `paperurl` comes from the bib `url`, else from a matching PDF in `files/publications/`. **Merge semantics:** for an existing file, only generated front-matter keys are replaced in place; other keys, the body, and line endings are preserved.
3. **`talks.py`** — Reads `talks.csv` (columns: title, type, url_slug, venue, date, location, talk_url, authors, presenter, link_url) and writes `_talks/YYYY-MM-DD-<url_slug>.md` with the same merge semantics. `link_url` falls back to `talk_url`, then to `files/<type lowercase>/<same name>.pdf`. Blank CSV cells don't delete existing fields.
4. **`talkmap.py`** — Geocodes each talk's `location` via Nominatim (network), writes `talkmap/` with getorg, adds venue names to `org-locations.js`, then rewrites the `<script>` in `talkmap/map.html` with a custom Esri-tiles Leaflet map.
5. **`build_cv.py`** — Renders `cv/cv.tex.j2` → `cv/build/cv.tex` using Jinja2 with LaTeX-safe delimiters (`((* *))`, `((( )))`, `((= =))`). Pulls from `_config.yml` (name), `_cv_text/objective.md`, `_data/cv/*`, `_teaching/`, `_publications/` (split by category), and `_talks/` (talks with `type: Seminar` or `cv_section: additional` go under "Additional Presentations", others under "Conference Abstracts"). Bolds "Tillman M" in author lists. All data is treated as **plain text and LaTeX-escaped** — never write LaTeX in data files. Files starting with `_` are skipped (Jekyll convention). If `latexmk` exists, compiles and copies to `files/cv.pdf`.

## Build & deploy

- **Local:** `./update_research_output.zsh` (needs network + activated venv + Ruby/bundler), then review at `http://localhost:4000`, commit, push. Site-only preview: `bundle exec jekyll serve -l -H localhost`. `_config.yml` changes require restarting the server.
- **CI (push to `master`):** `pages.yml` installs Python deps, runs `build_cv.py`, compiles the PDF with `xu-cheng/latex-action`, copies it to `files/cv.pdf`, builds Jekyll with `JEKYLL_ENV=production`, and deploys to GitHub Pages. Network-dependent steps (ORCID, geocoding) are **not** run in CI; their outputs must be committed.

## Conventions & gotchas

- **Underscore prefix = hidden.** Files like `_publications/_2026-04-01-...md`, `_talks/_2026-11-14-AAPM&R.md`, `_cv_text/_objective_seeking_postdoc.md` are skipped by Jekyll and by `build_cv.py` — used for drafts/in-review items.
- **Generated vs. hand-edited:** `_publications/` and `_talks/` front matter is partly generated. To add a field permanently, either add it to the source (`talks.csv` / ORCID) or add a non-generated key (e.g. `doi`, `cv_note`, `cv_section`), which the merge preserves. Editing a generated key by hand will be overwritten on the next run.
- `talks.csv` is the source of truth for talks; at last check `_talks/` had one more visible file than the CSV had rows, so some talk files may exist only by hand.
- **Known duplicated concept (NOTE 3 candidate):** the talk-type → label mapping ("Poster presentation", "Podium presentation", default "Oral presentation") and the "presenter defaults to first author" rule live both in `site_updater/build_cv.py` (`PRESENTATION_LABELS`, `main()`) and in `_includes/talk-presenter.html`. They must be kept in sync manually.
- Similarly, the `yaml_str` helper and the front-matter merge logic are duplicated between `pubsFromBib.py` and `talks.py`.
- There are currently **no automated tests** in the repo (NOTE 2 implies adding them when fixing issues).
- `.DS_Store` files are present on disk but gitignored (the user works on macOS).
- Commit history is on `master`; commit messages are short and informal.
